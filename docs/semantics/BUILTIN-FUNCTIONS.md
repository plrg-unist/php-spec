# Initial function namespace at the pinned CLI profile

The pure `$pfunction_builtin(ptbytes)` predicate records the 780 global function
names initially registered by this project's PHP 8.5.10 CLI, NTS, 64-bit build.
It performs ASCII case folding using the existing name helper. A registered name
is occupied even when execution of its ordinary-library body is unsupported.
The table does not implement those functions or close their runtime obligations.

`scripts/generate-builtin-functions.py` derives the table from the configured C
registration tables. It preprocesses the 13 translation units containing Core,
11 extension tables and CLI additions, using the local PHP build configuration
and original imported source headers. Lexbor, Reflection and URI register no
ordinary global function table; their module entry declarations retain explicit
NULL checks. The configured module sequence comes from
`.tools/php-build/main/internal_functions.c` and must match the pinned build.
Changed modules fail generation rather than silently falling out of the table.
The generated specification contains only byte literals and pure rules.

The generator never invokes PHP. Its source manifest binds all non-system C,
header and generated build inputs actually read, and preserves the exact
preprocessor output and diagnostics under `.tools/builtin-entries-*`.
`python3 scripts/generate-builtin-functions.py --check` checks reproduction after
the local PHP dependency build. The generated byte table is a runtime input;
neither the C preprocessor nor the generated build manifest is used to answer
semantic calls.

`tests/semantics/builtin_functions.py` separately enumerates native registration
metadata and compares the exact name set with the source-derived table. Its pure
SpecTec checks exercise every lowercase and uppercase name and absent names,
including namespace-qualified spellings, NUL bytes, disabled mbregex support and
the separate parser-helper extension. Native metadata is validation evidence,
not generator input and not an evaluation operation in the PHP semantics.

The initial profile uses `-n`, no dynamically loaded extension and an empty
`disable_functions`. This matches the existing semantic oracle profile;
`main/main.c` installs the default empty setting and invokes
`zend_disable_functions`, whose implementation removes configured names from the
function table in `Zend/zend_API.c`. Nonempty disabled-function lists, later `dl`
registration and different builds require explicit state/configuration support;
they are not represented by this fixed initial table. The parser-only native
extension's functions are intentionally absent from the runtime namespace.

Named declaration compilation checks builtin occupancy after successful body
compilation, at the same point as other early-binding duplicate checks.
Conditional and nested declarations check occupancy when activated. Lookup must
keep three outcomes distinct: an active user declaration, an existing builtin
whose execution may still be unsupported, and an absent function. Function
namespace fallback and import resolution continue to use the existing lexical
name rules. No engine execution supplies a semantic lookup or callable result.
