# Statics in main and parser-backed scripts

Static declarations in the initial script use the same persistent reference-cell table as named-function statics. The source declaration identifies a slot; absence is uninitialized and a cell containing null is initialized. Stored initializers, evaluated initializers, duplicate-name priority, source lines, local aliases and copy-on-write reuse the named-function rules.

At main scope the active environment is the global symbol table. Binding a static variable replaces that global name with the persistent cell; an earlier reference alias keeps its previous cell. Unsetting the global name leaves the persistent slot initialized, and revisiting the declaration binds the same cell again. Main `$_GET` direct, computed-name and `$GLOBALS` access observe that global binding. This differs from the hidden local CV used by a named-function static declaration with a superglobal name. A variable named `GLOBALS` remains distinct from the direct global-table view.

Initializer calls move the main symbol table into the existing global-table owner and restore it before the pending main binding resumes. Persistent static roots stay outside frames. The established binding operation therefore updates the correct table without a second table copy or a new synchronization layer. Main and named-function declarations with the same spelling retain separate persistent cells.

The unit code contains descriptors for nested functions as well as main statements. Resume validation identifies a main slot from an actual initial-unit declaration outside every named-function source body and authenticates its static descriptor against compilation. Main tasks require main context; initialized main slots remain valid while a function is active. Saved main continuations validate their restored source/context without borrowing the active callee's result or requiring its global-table field to be empty. Arbitrary consistent cell values and reference aliases remain valid; guards do not reconstruct initialization history.

Parser-backed eval/file top-level slots additionally require an authentic source binding and a live source-end owner when executing a declaration. Source ancestry excludes function, method, Closure, arrow and property-hook bodies. Source teardown leaves callable-owned slots to their existing callable lifetimes. Cell provenance can remain valid independently of a live task; a retired source cannot borrow an old static declaration as new work.

Normal source end and explicit return release initialized top-level slots in compiler declaration order while retaining the source context. Ordinary destructors therefore still see the dynamic frame. The already copied return operand stays rooted during release, and escaped references keep their cells alive. Later eval responses now admit the state after source statics execute. The [source-static review](../../coverage/semantics/source-static-retirement-review.json) separates the affected source, three independent normal originals and genuine public state frontiers.

With a real Closure caller, top-level eval/file declarations use the source-owned table and preserve the caller's own static cells, captures and scope metadata. Revisiting a declaration in one unit rebinds its cached cell; a new parser-backed unit initializes a fresh cell. Escaped references survive normal table retirement and remain separate from later units. Nested eval tables likewise retain separate source identities. The [identity review](../../coverage/semantics/source-static-identity-review.json) records this separate cut.

Body throws retire source slots before the source context crosses to the caller. Each decrement keeps the pending Throwable rooted through the existing eager destructor operation. A normal-end destructor throw leaves the remaining table slots to be released in compiler order before caller catch; a destructor replacing a body exception retains that exception in its Previous chain. The [throw review](../../coverage/semantics/source-static-throw-review.json) records these separate source and production-unwind frontiers.

Graceful exit keeps an authenticated source-end suffix while retiring the table through real steps. Callee locals retire before the source table; nested eval/file tables retire from inner to outer before shutdown. Destructor source reentry validates the saved exit barrier by source-unit identity, while executing release and crossing still require the current context head. Escaped references retain their cells and objects through shutdown. The [exit review](../../coverage/semantics/source-static-exit-review.json) separates exact originals, saved parser-resume ownership and production cleanup checks.

Source-table destructors that replace exit retain authentic user execution through saved callbacks and remaining-slot cleanup before caller catch. Replacement exceptions keep their Previous chain without treating the internal exit as a Throwable. A separate request exit-status register survives caught replacement; integer/default exit overwrites it, string exit preserves it, and a nested reset can change it while an older exit still unwinds. The [status review](../../coverage/semantics/source-static-exit-status-review.json) separates owner/catch and status cuts.

Hard-fatal shutdown roots and wider destructor/return interactions remain required. Wider method/trait/inherited identity and lifecycle behavior retain their earlier partial scope. No static/storage family closure is claimed.

The semantic table is released one declaration slot at a time to preserve observable destructor order.

`ZEND_FUNCTION(exit)` in `zend_builtin_functions.c` writes `EG(exit_status)` for the integer/default branch and leaves it unchanged for strings. An internal unwind controls execution independently of that request register.

`ZEND_INCLUDE_OR_EVAL` runs a fresh `new_op_array` with the caller's symbol table. `ZEND_BIND_STATIC` selects that executing op-array's own static table; sharing local names does not transfer static ownership into the caller Closure.
