# Real closure instances and explicit captures

This checkpoint targets the pinned PHP 8.5.10 CLI configuration. It introduces real closure values created by explicit anonymous-function expressions, with separate source templates and runtime object identities. The exact1017/9325 implementation and canonical CLI are bound by the [runtime evidence](../../coverage/semantics/closures-runtime.json) and [independent review](../../coverage/semantics/closures-review.json).

`POBJECT` refers to a shared `HOBJECT` allocation. The object store has a real-closure payload containing its template origin, ordered lexical captures, and its own initialized static slots. Templates reuse checked function signatures, defaults, local-variable inventories and source metadata, but never enter the named-function registry. Two evaluations of one expression create different instances; copying a closure value preserves the same identity.

Creating a closure reads captures in source order. Value captures retain a copied PHP value, including shallow array sharing and embedded references. Reference captures retain the actual reference cell, materializing null when necessary. A partially constructed instance has an explicit capture cursor and uninitialized suffix; its pending capture task is its sole owner. Completion transfers that owner to the result. Each invocation binds fresh local values for value captures and aliases the retained cells for reference captures after parameter/default/variadic receives and before body execution.

A selected closure instance remains owned while arguments execute, including nested calls which unset the original global callee variable. Pending targets and active/saved call contexts carry that owner through all three argument lanes. Return values and references use the shared return protocol. Fatal cleanup releases temporary owners while preserving surviving caller, capture, array and reference owners.

Closure statics belong to the instance rather than the request-wide static table. Missing slots are uninitialized; an initialized null slot is present. Initialization rechecks the slot after evaluating its expression, so a recursive invocation that initialized it first wins. Static wrappers remain distinct from other declaration slots; ordinary lexical, local, parameter and global aliases may refer to those wrappers.

The heap graph includes object-to-capture and object-to-static edges. Backing records do not root objects. Releasing zero-reference allocations cascades through the same graph used for arrays and cells; unreachable reference cycles survive reference-count pruning. This is not an implementation of PHP's cycle collector, collection thresholds or source-visible GC services.

Closure truth is true, strict identity uses the shared instance, and distinct real closures are uncomparable under the custom object comparison handler. Mixed numeric comparisons emit notices where PHP visits those operands, including inside array comparisons; identity, count, key and first-mismatch short circuits suppress unvisited effects. Explicit integer/float casts instead emit warnings and produce one. A closure-to-array cast creates a fresh array whose key zero holds the same instance; an object cast preserves the instance. String conversion and invalid arithmetic, bitwise, increment/decrement, key and dimension operations produce the corresponding PHP errors. Foreach sees no public properties, including the reference iteration path; captures are not exposed as properties.

State-aware type checking accepts closure objects for `object`, `callable` and the supported `Closure` class type, while scalar weak conversion still rejects a closure for `bool`. Diagnostics display `Closure` and traces display `Object(Closure)`. Registered function strings and pinned built-in function names are recognized for callable type tests. Invalid callback array shapes reject; potentially valid class/method callback forms whose services are not implemented remain explicit dependencies. The retained valid `[Closure, "fromCallable"]` type source is one such dependency, not a native-agreement row.

Public resume guards authenticate template metadata from the checked source compilation. They validate allocated object records, capture mode/length/progress, current creation scope and receiving context, and persistent slot ownership. Unallocated backing records and arbitrary consistently owned runtime capture/cell values remain permissible. Guards do not reconstruct earlier callee strings, capture values or initialization history.

The source catalogue and exact final identities are recorded in the accompanying reports. Arrow functions, ordinary object construction/property behavior, method and array-callable invocation, closure binding/call/clone, first-class callable creation, reflection and other Closure services, include/eval lifetime, and exception handlers remain separate obligations. No complete closure, object, GC or PHP-core family closure is claimed.

Pinned source routes: `zend_compile_closure_binding` and `zend_compile_closure_uses` in `Zend/zend_compile.c`; `ZEND_BIND_LEXICAL`, `ZEND_BIND_STATIC` and `ZEND_BIND_INIT_STATIC_OR_JMP` in `Zend/zend_vm_def.h`; `zend_create_closure_ex`, `zend_closure_free_storage`, `zend_closure_get_gc` and `zend_closure_compare` in `Zend/zend_closures.c`; standard cast/comparison handlers in `Zend/zend_object_handlers.c`; closure array casts in `Zend/zend_operators.c` and `Zend/zend_execute.h`. The evidence archive records exact pinned bytes for these routes.
