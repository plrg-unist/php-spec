# Dynamic string user-function calls

This slice executes expression-callee calls that select a registered user function by string. Callee evaluation and lookup finish before argument evaluation. The selected function then uses the existing positional, named and array-unpack send paths, typed/default receives, reference return acquisition and suppression cleanup. Changing or unsetting the name during argument evaluation cannot change that selection.

The pinned compiler distinguishes an initial parser string from an expression compiled later. Initial parser strings, including the existing parser-folded literal concatenations, use fully qualified lookup and can have known parameter modes. Expressions compiled later retain deferred argument modes even when their result becomes a constant string. Other evaluated operands use dynamic lookup. This is a source/compiler distinction, not a reason to reconstruct an earlier string from a paused state.

The new `CODECALL_INIT` entry records the call initialization instruction at the outer source call root. Callee child metadata remains separate. This preserves three different multiline locations: a nested callee call, the lookup instruction after evaluating that callee, and the eventual outer call. Undefined literal CV reads warn before a noncallable-value error. Scalar values are not coerced to callable strings. Runtime dynamic string lookup is case-insensitive and removes one leading backslash; missing-name diagnostics retain the original bytes but truncate at NUL as Zend's `%s` formatting does. Later compiled CONST strings use their raw emitted fixed name for lookup, retaining deferred argument modes. They do not apply the runtime leading-backslash removal.

`CALL_DYNAMIC` owns no duplicate argument list or historical name. The checked source root identifies its arguments, and `RESULT` owns the evaluated callee operand until lookup consumes it. Successful lookup clears that operand before scheduling the existing send task with a registered function origin. Saved callee frames continue to own their suspended tasks and restore the caller origin before lookup. The existing heap, reference-cell, frame and abrupt cleanup machinery handles retained owners.

Public resume validation binds the lookup task to an actual expression call, its source origin and both emitted lines. A scoped compiler projection checks the call initialization entry, outer/callee expression metadata and the classifier's ordinary CV-name result. A source CV must still be represented by its deferred variable operand; non-CV results may hold arbitrary consistent owning values or reference cells. Checks apply the active result only at the administrative lookup prefix. Saved tasks use their own restored origins. After true dynamic lookup, an arbitrary consistent registered function remains a valid selected state; validation does not invent the previous dynamic name. Initial parser strings and later compiled CONST strings retain their source-bound fixed target. An owning result that the fixed opcode does not consume cannot change that target.

Initial literal builtin calls, registered builtin body execution, array/object callables, static-method string calls and Closure values remain explicit dependencies. Future destructor behavior must join the existing callee-operand release point. This milestone does not close the callable family or the complete-core goal.
