# Arrow implicit captures and expression returns

This checkpoint extends the existing real Closure implementation with arrow expressions for the pinned PHP 8.5.10 CLI configuration. The [runtime evidence](../../coverage/semantics/arrows-runtime.json), [compiler contract](ARROW-COMPILER.md) and [independent review](../../coverage/semantics/arrows-review.json) bind exact implementation identities and measured source/state coverage. Arrow expressions create ordinary real closure instances with distinct identities and unregistered source templates; they add no object or value layout.

The compiler derives an ordered implicit capture list from the checked expression, removes the current arrow's parameters, and preserves the pinned nested-scope and array value-before-key discovery rules. CODEIMPLICIT names each binding at the actual FIELD5 expression root. CODEARROW distinguishes that root from a named function body and records the emitted return line without replacing the child expression descriptor. Static flags, signatures, defaults, argument modes and magic names use the existing template pipeline.

Creation copies a defined variable's value and dereferences an outer reference before capturing it. Array values retain shallow sharing and embedded reference cells. A missing variable is captured as undefined without a creation warning or null materialization. Requestless environment-dependent argv/argc reads retain their existing explicit boundary. Each invocation receives a fresh local copy, including an actually undefined local: a normal body read may warn, while isset/coalesce remains quiet. Defining the outer variable later does not alter the captured snapshot.

UNINITIALIZED is interpreted using the authenticated capture mode and current task cursor. It can denote a processed undefined implicit slot or a pending suffix; an explicit completed capture still requires a value/reference. A live capture task owns its partial object exclusively, including cursor=end before publication, and that object is not callable. A published implicit capture may remain undefined. Bounds, source, ownership and mode inconsistencies reject, while consistent cursor rebasing across undefined slots and arbitrary owned values remain valid. No earlier capture values are reconstructed.

Invocation uses the existing owning selected-instance carrier, parameter/default/variadic receives and active/saved contexts. Arguments may unset the original global callee owner without destroying the selected instance. The actual expression is evaluated at its checked source origin, followed by a source-authenticated value or reference return. Reference-returning arrows preserve the distinction between direct variable fetch and value/call results, including native notices and fresh invocation-local reference lifetimes. No synthetic checked return statement is inserted into the source tree.

A never arrow evaluates its expression as discarded, then reaches the shared typed fallthrough error if evaluation completes. It has a CODEARROW marker but no implicit RETURN task. A retained paused reference-returning call showed that the earlier generic demand helper incorrectly marked this expression as used despite matching full native output. The narrow source-kind/signature repair makes never-body calls unused, including through suppression, while ordinary arrow reference-call results remain used.

A second retained paused-state failure exposed a shared suppression guard that searched only named functions. The repair authenticates current and saved suppression owners against named functions and closure templates and excludes their nested scopes from MAIN ownership. Arrow, explicit-closure and named/MAIN controls cover the correction; saved-frame validation does not inspect an unrelated active result. Earlier explicit-closure acceptance evidence remains historical rather than being relabeled with this repair.

Ownership and object operations remain those of [real closures](SOURCE-CLOSURES.md): capture/static edges participate in the shared reference-count graph, and unreachable cycles are not removed by a reachability shortcut. Class-bound scope, ordinary object construction/properties, method and array-callable invocation, binding/call/clone, first-class callable creation, reflection and other Closure services, include/eval lifetime, exception handlers and cycle collection remain separate obligations.
